# Quickstart: Validating the Mi Perfil (Profile) Redesign

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

This is a validation guide, not an implementation guide — it documents how
to run and manually/automatically verify the redesigned Mi Perfil once
implemented. See `data-model.md` and `contracts/` for what "correct" means;
see `tasks.md` (generated by `/speckit-tasks`) for how to build it.

## Prerequisites

- Repo dependencies installed: `cd retro-rocket && npm install`
- Firebase auth emulator running (Mi Perfil requires sign-in):
  `npm run emulators` (separate terminal), or rely on `npm run e2e` which
  starts it automatically.
- The backend dev server running alongside the frontend for real
  `GET`/`PATCH /api/profile` responses: `npm run dev:all` (starts both
  `dev` and `dev:server`).

## 1. Run Mi Perfil locally

```sh
cd retro-rocket
npm run dev:all
```

Sign in and navigate to `/perfil`.

**Check**:
- Avatar (or fallback), display name, read-only email, primary provider
  badge, and member-since date all render correctly (FR-002).
- Edit the display name to a valid value and save — confirm it updates
  immediately, persists after reload, and shows a clear success
  confirmation (FR-003).
- Attempt to save an empty/blank display name — confirm it is blocked with
  a clear message before any request is sent (FR-003).
- Sign out — confirm the app returns to a signed-out state (FR-004).
- With an account that has one linked provider, confirm it shows as linked
  and the other as linkable; link the second provider and confirm it now
  shows as linked (FR-005). Confirm Apple shows as "not yet available",
  not as a broken action.
- With at least one connected AI assistant (or connect one via the MCP
  connector first), confirm it lists with its connection date, and that
  revoking it removes it from the list immediately (FR-006).
- Inspect "Exportar mis datos" and "Eliminar cuenta" with a screen reader
  (or the browser's accessibility inspector) — confirm both are announced
  as disabled and unavailable, not merely visually muted (FR-007).
- Confirm no request to any Firebase/Firestore/Firebase Auth endpoint
  appears in the network panel while performing any of the above (FR-008).

## 2. Verify the shared first-time-setup path is unaffected

1. Sign in with a brand-new account (or clear the emulator's user data) so
   the landing page renders its first-time profile-setup form
   (`UserProfileForm` with `isFirstTime={true}`).
2. Confirm the form renders correctly and completing it navigates you into
   the app as expected, with no regression to the landing page's own
   already-shipped layout around it (FR-009).

## 3. Automated checks

```sh
cd retro-rocket

# Type-check and lint
npm run type-check
npm run lint

# Unit/component tests + coverage gate (branches 78 / functions 64 / lines 50 / statements 50)
npm run test:coverage

# Architecture boundary — Mi Perfil MUST NOT import the Firestore SDK
npx vitest run src/test/architecture/profile-no-firestore.test.ts --config vitest.config.ts

# If any new/changed design tokens were introduced, confirm WCAG contrast math still holds
npx vitest run src/test/lib/theme/contrast.tokens.test.ts --config vitest.config.ts

# E2E: profile, first-time-setup (within authentication), and accessibility (WCAG 2.1 AA, both themes, all states)
npm run e2e -- profile.spec.ts authentication.spec.ts accessibility.spec.ts
```

**Expected outcome**: all of the above pass with zero regressions and zero
new WCAG 2.1 AA violations (SC-002), per
`contracts/functional-parity-contract.md` and
`contracts/accessibility-interaction-contract.md`.
