# Quickstart: Validating the Options Menu & Facilitator Menu Redesign

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

This is a validation guide, not an implementation guide — it documents how
to run and manually/automatically verify the redesigned options menu and
facilitator menu (including the new mobile entry point, FR-013a) once
implemented. See `data-model.md` and `contracts/` for what "correct" means;
see `tasks.md` (generated by `/speckit-tasks`) for how to build it.

## Prerequisites

- Repo dependencies installed: `cd retro-rocket && npm install`
- Firebase auth emulator running (board access requires sign-in):
  `npm run emulators` (separate terminal), or rely on `npm run e2e` which
  starts it automatically.
- The backend dev server running alongside the frontend for real
  realtime/REST responses: `npm run dev:all` (starts both `dev` and
  `dev:server`).
- At least two signed-in browser profiles/accounts: one who owns a board
  (facilitator) and one who joins it as a non-owner participant.

## 1. Run the board locally

```sh
cd retro-rocket
npm run dev:all
```

Sign in as the board owner, create a board, and navigate to `/retro/:id`;
sign in as a second account in another profile/browser and join the same
board.

**Check, at a desktop viewport width:**

- As either participant, open the options menu — export, copy ID, share,
  and exit are all present and functional (FR-002); export opens the
  existing `ImprovedExportPopover` unchanged.
- As the owner, open the facilitator menu — confirm the controls tab is
  active by default (FR-008), then exercise each tab:
  - Controls: toggle the action items column; create a timer (custom
    duration and a quick preset), start/pause/reset/delete it, and confirm
    the other participant sees the live status update in real time (FR-004).
  - Sentiment: enable/disable analysis, change the model, pause analysis,
    expand advanced settings (confidence threshold, batch size,
    auto-analysis), and observe the error state's presentation (FR-005).
  - Team Mood: confirm the disabled/initializing/live-report states are
    each legible and distinguishable (FR-006).
  - Notes: add, edit, and delete a private note (with delete confirmation);
    confirm the non-owner participant cannot see it (FR-007).
- As the non-owner participant, confirm the facilitator menu trigger is
  entirely absent, not merely disabled (FR-003).

**Check, at a mobile viewport width (FR-013a — new capability):**

- As either participant, locate and use the new mobile entry point for the
  options menu — every capability above remains reachable and completable.
- As the owner, locate and use the new mobile entry point for the
  facilitator menu — all four tabs and their capabilities remain reachable
  and completable, including the live timer status update.
- As the non-owner participant, confirm the facilitator menu's mobile entry
  point is also entirely absent (FR-003 applies identically on mobile).

## 2. Verify accessibility and interaction requirements

1. **Keyboard/touch reachability (FR-009, FR-013a, SC-003, SC-008)**: Tab to
   the options menu trigger and the facilitator menu trigger using only the
   keyboard, at both a desktop and a mobile viewport — confirm each
   receives visible focus, opens via Enter/Space, arrow-keys between
   facilitator tabs, and dismisses via Escape, with no mouse involved.
   Separately, using a touch-emulated viewport (devtools device toolbar) or
   a real touch device, confirm every item/tab/control — including the new
   mobile entry point's own trigger and close affordance — is operable
   without any prior hover/pointer-enter event.
2. **Reduced motion (FR-012)**: enable `prefers-reduced-motion: reduce` and
   repeat: open/close the options menu, open/close the facilitator menu and
   switch through all 4 tabs, open/close the new mobile entry point for
   both — confirm every one still completes and communicates its result
   without relying on animation.
3. **Responsive layout (FR-013)**: resize across mobile, tablet, and
   desktop widths — confirm a way to open both menus is present at every
   size (owner-only for the facilitator menu) and that once open, every
   option/tab/control remains legible and reachable; confirm locale text
   (English/Spanish) doesn't break the layout at any width (Edge Cases,
   `spec.md`).

## 3. Automated checks

```sh
cd retro-rocket

# Type-check and lint
npm run type-check
npm run lint

# Unit/component tests + coverage gate (branches 78 / functions 64 / lines 50 / statements 50)
npm run test:coverage

# Architecture boundary — no direct Firestore access from these components
npx vitest run src/test/architecture/retrospective-board-no-firestore.test.ts --config vitest.config.ts

# If any new/changed design tokens were introduced, confirm WCAG contrast math still holds
npx vitest run src/test/lib/theme/contrast.tokens.test.ts --config vitest.config.ts

# E2E: facilitator/countdown, team mood, export (options menu trigger), the
# board itself, and accessibility (including the new mobile-viewport coverage)
npm run e2e -- facilitator-countdown.spec.ts team-mood.spec.ts export.spec.ts retrospective-board.spec.ts accessibility.spec.ts
```

**Expected outcome**: all of the above pass with zero regressions and zero
new WCAG 2.1 AA violations (SC-002, SC-003), including new mobile-viewport
coverage added to `accessibility.spec.ts` (`research.md` §6) — see
`contracts/functional-parity-contract.md` and
`contracts/accessibility-interaction-contract.md`.

## 4. Design-process artifacts to confirm exist (FR-015, SC-005, SC-006)

- `data-model.md`'s `Visual Direction` table lists 2-3 candidates, exactly
  one `selected`, each with its own committed `mobileEntryPointPattern`,
  reviewed by the product owner with `rejectionReason`s filled in for the
  rest.
- `contracts/visual-direction-review-contract.md`'s required-before-review
  checklist is satisfied for the selected direction, including its
  mobile-entry-point demonstration.
- `contracts/functional-parity-contract.md`'s verification procedure has
  been run against both the baseline and the final implementation.
- `contracts/accessibility-interaction-contract.md`'s checklist is fully
  checked, not left partially unchecked.
- A structured design review against Apple HIG principles (clarity,
  deference, depth) closes with zero unresolved high-priority findings
  (SC-005) — recorded in `design-review.md` (analogous to features
  028/029/031/033's own design-review documents).
